[HttpPost("register")]
public async Task<IActionResult> Register(RegisterDto model)
{
    var user = new ApplicationUser
    {
        UserName = model.Email,
        Email = model.Email
    };

    var result = await _userManager.CreateAsync(user, model.Password);

    if (!result.Succeeded)
        return BadRequest(result.Errors);

    return Ok("User created successfully.");
}

public class RegisterDto
{
    public string Email { get; set; }
    public string Password { get; set; }
}

[ApiController]
[Route("api/[controller]")]
public class AuthController : ControllerBase
{
    private readonly IAuthService _authService;

    public AuthController(IAuthService authService)
    {
        _authService = authService;
    }

    [HttpPost("login")]
    public async Task<IActionResult> Login(LoginRequest request)
    {
        var user = await _authService.ValidateUserAsync(
            request.Username,
            request.Password
            );

        if (user == null)
            return Unauthorized();

        var token = _authService.GenerateToken(user);

        return Ok(new
        {
            accessToken = token
        });
    }
}

How do you implement JWT authentication in ASP.NET Core?

Ans:
I configure AddAuthentication().AddJwtBearer() with the issuer, audience, signing key
and token validation parameters. During login, the identity provider authenticates 
the user and issues an access token. The client sends that token as a Bearer token in
the Authorization header. ASP.NET Core JWT middleware validates the signature, issuer,
audience and expiration and creates the ClaimsPrincipal. I then use [Authorize], 
roles, claims or policies for authorization. In a microservices architecture, 
I prefer a centralized OAuth2/OIDC identity provider rather than generating tokens 
independently in every microservice.

Note:
The Identity Provider or Authorization Server generates the JWT access token. 
The client sends it as a Bearer token, and each ASP.NET Core microservice validates 
the token and applies authorization using roles, claims, or policies.  

And for service-to-service calls, you can use mTLS and/or OAuth2 client-credentials 
tokens, depending on the security requirements.

Authorization Server → gives the token

Resource Server → accepts and validates the token

Client → uses the token

JWT → carries the identity/claims/permissions

In your kind of architecture, you might have:

API
 │
 ├── Validate request             → Sync
 │
 ├── Check Redis                  → Async
 │
 ├── Query MongoDB/PostgreSQL     → Async
 │
 ├── Call another microservice    → Async
 │
 ├── Publish Kafka message        → Async
 │
 └── Calculate some values        → Sync


I use synchronous methods for CPU-bound or simple in-memory operations where there 
is no waiting involved. I use asynchronous methods for I/O-bound operations such as 
database queries, HTTP calls, Redis, file operations, and messaging. Async allows 
the ASP.NET Core thread to be released while waiting for I/O, which improves 
scalability under high concurrency. I don't make every method async unnecessarily 
because async doesn't provide a benefit for simple CPU-bound operations.
