1. Can we create an object of an abstract class?
No
// Compile-time error
Employee emp = new Employee();

2. Can an abstract class have a constructor?
Answer: Yes. The constructor is called when a derived class object is created.

3. Can an abstract class have non-abstract methods?

Answer: Yes.

4. Can an abstract class contain only normal methods?
Answer: Yes. A class can be declared abstract even if it has no abstract methods, which prevents it from being instantiated directly.

When to Use an Abstract Class

Use an abstract class when:

Multiple classes share common code.
You want to provide a base implementation.
You want to force derived classes to implement specific methods.

Interview Questions
1. Can a static class have a constructor?

Answer:
Yes, but only a static constructor.

2. Can a static class implement an interface?

Answer:
No. Static classes cannot implement interfaces because interfaces define instance behavior.

3. Can a sealed class have a constructor?

Answer:
Yes. Like any normal class, it can have constructors.

4. Why use a sealed class?

Answer:
To prevent inheritance when you want to:

Protect implementation
Prevent overriding
Improve API design
Restrict extension

Easy Way to Remember
Normal Class → Create object + Inherit + Be inherited
Static Class → No object + Only static members
Sealed Class → Create object, but inheritance is blocked

Real-Time Use of Sealed Class

1. The virtual Keyword
public class Car 
{
    // Has a body. Inheritance is NOT required.
    // Overriding this in a child class is optional.
    public virtual void StartEngine() 
    {
        Console.WriteLine("Engine started with default settings.");
    }
}



2. The abstract Keyword

public abstract class Animal 
{
    // No body. You MUST inherit this class to use it.
    // The child class MUST override this method.
    public abstract void MakeSound(); 
}

public class Dog : Animal 
{
    // Required implementation
    public override void MakeSound() 
    {
        Console.WriteLine("Bark!");
    }
}
