Interview answer — "How do you deploy .NET 8 microservices on AWS EC2?"

You can answer like this:

"First, I containerize or publish each ASP.NET Core 8 microservice separately. For a direct EC2 deployment, I provision Linux EC2 instances in private subnets, install the .NET 8 runtime, and copy the published application artifacts to the server. Each microservice runs on its own Kestrel port and is managed by systemd so that it automatically starts and restarts if it fails.

I put Nginx or preferably an Application Load Balancer in front of the services. I expose only 80/443 publicly and keep the individual application ports private. For high availability, I deploy multiple EC2 instances across Availability Zones behind an ALB and use an Auto Scaling Group.

For persistence, I use RDS rather than hosting the database on EC2. Redis can be provided through ElastiCache, files through S3, and asynchronous communication through SQS. Secrets such as database credentials are stored in Secrets Manager and accessed using IAM roles rather than hardcoded credentials.

Finally, I use CloudWatch for logs, metrics and alarms and automate deployment through CI/CD. This gives me scalability, security, observability and high availability."

That is the Senior/Lead-level answer rather than simply saying "I copy the DLL to EC2 and run dotnet app.dll."
